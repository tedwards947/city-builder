# AGENT.md

This file provides guidance to AI agents when working with code in this repository.

**Concretta**: a browser-based 2D top-down city builder (SimCity-style). "Concretta" is the game's name (owner, 2026-11-19); the repo and folders stay `city-builder`. Use the name in player-facing text.

**IMPORTANT** 
I'm using a somewhat limited Pro plan so tokens and context length REALLY MATTER! Please ask before importing large resources and please be dilligent before adding too much context!


See the backlog/wishlist at WISHLIST.md

## Target Tech Stack

- TypeScript + Vite
- Vitest for tests
- Canvas 2D renderer (MVP); PixiJS later
- Cloudflare Pages for hosting
- IndexedDB for local saves (manual slots + autosave in slot 0); Cloudflare Workers + R2/D1 for cloud saves (future phases)
- Save files: the Save dialog exports the current city as a `.citysave.json` file and the Load dialog imports one (`src/persistence/SaveFile.ts`: JSON, layers as base64, upgraded through `migrate`). IndexedDB saves are tied to one site address (including the port), so a file is the way to move a city between ports, browsers or machines, or to hand one to an agent for testing

## Core Architecture Principles

Load-bearing decisions — don't change without good reason.

**Typed-array tile layers:** Each world property is a flat `Uint8Array[width * height]`. Adding a simulation concern = adding a layer. `Grid.idx(tx, ty)` = `ty * width + tx`. Never use arrays-of-objects for tile data.

**ECS-style, not inheritance:** Tiles have component layers; entities (buildings) are small objects in `world.buildings[]`. A new concern = a new component + system, not a new class hierarchy.

**Tick-based sim, decoupled from render:** `Scheduler` fires at a fixed rate (2 ticks/sec at 1×). Render runs at display refresh. The sim knows nothing about rendering.

**Systems communicate through world state and EventBus:** Systems write to layers; later systems read them. Cross-system signals go through `EventBus`.

**Command pattern for all mutations:** Every player action is a `Command` with `execute(world)` / `undo(world)`. Commands snapshot tile state to reverse themselves. Never mutate world state directly from input handlers.

**`restoreTile` in Command.ts must be kept in sync** with every new building type — it keeps `world.buildings[]` consistent on undo. When adding a new building type: update `BUILDING_*` constant, add `placeBuilding` / `clearTile` handling in World, add `restoreTile` handling in Command.ts.

**`snapshotTile` / `restoreTile` must cover every player-visible persistent layer.** They currently include abandoned, distress, vegetation and visualVariant as well as zone/road/building/devLevel. A layer missing from the snapshot becomes an undo exploit (precedent: bulldoze + undo revived abandoned buildings for free).

**Seeded deterministic RNG:** Use `mulberry32(seed)` only. Never call `Math.random()` in sim logic.

**Data-driven balance:** All costs, rates, and thresholds live in `balance.ts`. No magic numbers in code.

**Renderer behind an interface:** All world→screen math goes through `Projection`. `Projection.depth()` returns `0` for top-down, `tx+ty` for isometric — this is the isometric swap hook.

**Traffic is flow-based, not agent-based** (`TransitSystem`, tests in `transit.test.ts`). No trips or routes are simulated. Traffic is a list of MARKETS (`MARKET_DEFS` in `src/sim/TrafficData.ts`): shopping (homes → commerce), jobs (homes → industry) and goods (commerce → industry: each shop fetches from the nearest industry with output to spare). Each market has its own map, door capacities, prices and road volumes, and `TransitSystem`, `TrafficOverlay` and the debug tools all loop over the list — **to add or change a kind of trip, edit `MARKET_DEFS` (and its rate/capacity keys in `BALANCE.transit`), not the pass.** Per iteration and per market: (1) a Dijkstra flood gives each road tile its travel time to the nearest "door" (road tile beside a developed destination zone), a tile costing `1 / speedMult`, more when loaded past `freeFlow` (`congestionDelay`); (2) each origin's trips are put on its best adjacent road and swept downhill, each tile handing its traffic to ALL nearer neighbours, weighted by how little of a detour each is (`ROUTE_SPREAD`) — traffic ends at the first door it reaches; (3) a door that got more than its capacity (zone levels × `shopCapacity`/`jobCapacity`/`goodsCapacity`) spills the excess to doors with room within `SPILL_RADIUS` road tiles, and what still does not fit stays there as over capacity. Congestion = total volume / class capacity; accessibility comes from travel time (homes: nearer of shops or jobs; commerce and industry: homes). Highways carry traffic but give zones no access (same rule as growth). **Stability matters more than cleverness here.** Steps 2 and 3 have no feedback on purpose; an earlier version balanced door loads with iterated "prices" and never settled in a dense city (one new road tile reshuffled hundreds of roads for a minute). The only feedback is congestion → travel time → routes, kept calm by the multi-neighbour split, eased cost changes (`COST_EASE`) and per-tile averaging of volumes that keep changing (`_merge`). If you add a mechanism that feeds back into routing, re-run a stability check like the 'one new road tile in a congested town' test. A pass is a few iterations (more on the first pass, after a road edit and from `recompute()`); `world.traffic.settled` says when it has stopped moving. `main.ts` calls `refreshIfRoadsChanged()` every frame so road edits show at once, also while paused. The vehicles in `VehicleLayer` are cosmetic. The last pass is published as `world.traffic` (`src/sim/TrafficData.ts`: travel-time maps and per-flow volumes, not saved). `src/render/TrafficOverlay.ts` draws the traffic overlay from it as its own layer after `renderer.render()` (road load past 100%, commute tint on zones, route trace on hover); `CanvasRenderer` has no traffic overlay of its own any more. With `?debug=true` (`src/debug.ts`) the tile inspector adds traffic numbers and `TrafficTuningPanel` shows sliders that edit `BALANCE` live and call `TransitSystem.recompute()`.

**Buildings in traffic** (`src/sim/buildingTraffic.ts`, tests in `buildingTraffic.test.ts`). `BALANCE.transit.buildings` has a row per building kind (`BuildingTrafficRow` in balance.ts): `takes` (trips per tick it can take, per market: its access roads become doors), `sends` (trips it puts on the road, per market), `incomePerTrip` (money per trip taken; trade, not tax) and `demandMult` (city-wide R/C/I growth demand while one of the kind stands on a road, each kind counted once). Amounts are shared evenly between the streets and avenues touching the footprint. A new building (airport, landmark) joins traffic with a row and no engine code. `addTripProvider` in `TrafficData.ts` is the mirror of `addDoorProvider`: a building as a source of trips. A fifth market, `visitors` (homes → buildings, `transit.tripsVisitors`), runs only while a building takes visitors. What arrives at a building's door beyond its room drives on along the roads to the nearest zone door (`TransitSystem._passOn`), so a small door near homes takes its few trips and the rest are still on the road. Building doors carry traffic but give homes no accessibility: the accessibility block in `TransitSystem` counts zones only (owner's rule; otherwise a school that takes commuters is a workplace next door and tax income rises). The other way round, a building that sends shoppers counts as customers for commerce, and one that sends job seekers as workers for industry (shops across the street from the airport are next to their customers). The four maps accessibility is measured on are on `world.traffic`: `toShops`, `toJobs`, `toCustomers`, `toWorkers`. `buildingTripsAt(world, tx, ty)` gives the inspector a building's trips and income. The airport's row has the Balance Lab's numbers (below); police, fire, school and hospital take 1 job trip each (owner, 2026-11-18; commuters who find one full drive on, `_passOn`). The seaport keeps its own rules (`sim/seaport.ts`).

**The airport** (`BUILDING_AIRPORT` = 13, tests in `airport.test.ts`): a 12×5 block anchored top-left; rows from the north are terminal, tower and hangar (dy 0–1), apron (dy 2–3), runway (dy 4). Placement rules in `buildingShapes.ts`: `noRotation` (every rotation gives the same shape and it is stored at 0) and `onePerCity` (`checkPlacement` sets `alreadyBuilt`, `placeBlocker` returns 'alreadyBuilt', the command fails with that reason). Shape role `'frontage'` (dx 2–9, dy 0): a kind with frontage tiles is entered only from streets and avenues beside those (`World.buildingAccessRoads`), so the airport's doors are the roads along its terminal. Its traffic is its row in `BALANCE.transit.buildings`: cost 2,000,000, upkeep 150 a tick, takes 100 visitors a tick at 6 each, sends 30 shoppers and 10 job seekers, commercial demand × 1.1 (Balance Lab, owner 2026-11-18). The `airport` tool exists in `InputController`; the toolbar does not offer it yet.

**Changing a building kind's shape** (`World.fitBuildingsToShapes`, tests in `reshapedBuildings.test.ts`). A building's tiles are not saved: they come from its anchor and the kind's current shape. So after a shape change, every load fits saved buildings to the new shape: a building takes the extra tiles if they are free (land with no building, zone or road), otherwise it is removed and its cost paid back. Growing a shape is covered; shrinking one is not (the dropped tiles would be left as orphans), so add that before shrinking a shape.

**The airport request** (`airport` in `sim/requests.ts`, tests in `airportRequest.test.ts`): a city-wide request asked while no airport stands and cash is at least `BALANCE.buildings[13].cost` (`canAsk` on the kind), met once an airport has a road along its terminal. Numbers in `politicalCapital.requests.kinds.airport`: long deadline, no penalty, a reward of 250 PC (about one full bar where it first fires; Balance Lab, owner 2026-11-18), `once` (never asked again after it is met) and `cooldownDays` (after it expires). `world.politics.requestNotBefore` (saved) holds, per kind, the tick before which it will not ask. It is a `standing` kind: while open it does not stop its neighbourhood asking for something else and does not take a `maxOpen` slot, but it only opens when a slot is free.

**Rail track** (RAIL_DESIGN.md phase 1, `sim/rail.ts`, tests in `railTrack.test.ts`): track is its own saved tile layer, `world.layers.rail`, one bit per level (`RAIL_GROUND`, `RAIL_ELEVATED`, `RAIL_SUBWAY`) so later levels need no save change; only ground track can be laid so far. `world.layTrack` / `BuildTrackCommand` / the `rail` tool (dragged like a road; no toolbar button yet) put it on land with no building or zone, or on water at the bridge multiplier. Track may share a tile with a street or avenue as a **level crossing**, which is always straight: `trackBlocker` refuses a highway, a road bend or a road junction, and `trackBlocksRoad` (called by `World.setRoad` and `roadBuildCost`) refuses a road over a bend or junction of track, along the track, or joining a crossing from its track side. `railLinks(world, i)` gives the neighbours a track tile is joined to; a crossing joins only along its track. Track keeps zones, buildings, trees and water edits off its tile; the bulldozer clears it (a crossing goes with its road). `world.railVersion` goes up on every change to the layer. Numbers in `BALANCE.rail` (placeholders). Track carries no traffic yet.

**Rail levels (phase 2, A)** (tests in `railLevels.test.ts`): `world.layers.rail` holds one bit per level, `RAIL_GROUND` 1, `RAIL_ELEVATED` 2, `RAIL_SUBWAY` 4, and a tile may hold any mix. `RAIL_SURFACE` = ground | elevated: the levels that take up the surface. Track joins only track of its own level: `railLinks(world, i, level)`, `trackBlocker(world, tx, ty, level)`, `trackBuildCost(…, level)`, `World.layTrack(tx, ty, level)` all default to ground. Elevated goes over land, water, any road (no level crossing) and ground track, never over a building or a zone, and nothing but a road or ground track may go under it afterwards. Subway goes under anything, and anything may be built over it. Prices in `BALANCE.rail.track[2]` and `[4]` (placeholders); only ground pays the bridge multiplier. The bulldozer clears ground and elevated track with the tile and leaves a subway; in the UNDERGROUND VIEW (`underground` in main.ts, key U, passed to the renderer as `RenderOptions.underground`, and set on `InputController.underground`) it takes out the subway only (`RemoveSubwayCommand`). Tools `railElevated`, `railSubway` (drag; Auto mode is ground only so far; picking `railSubway` turns the underground view on). **Not yet:** nothing rides elevated or subway track (TransitSystem reads ground only), there are no ramps or subway stations, and graphics has not drawn them.

**Ramps and the subway station (phase 2, B)** (tests in `railRamps.test.ts`): `BUILDING_RAMP_ELEVATED` 16 and `BUILDING_RAMP_SUBWAY` 17 are 2×1; the anchor is the GROUND end (role `'rampLow'`, carries `RAIL_GROUND`) and (1, 0) at rotation 0 the high or deep end (`'rampHigh'`, carries `rampLevel(kind)`). Each end joins its own level only straight out, away from the other end (`trackSides`, `levelSides`); the join across the levels is `rampOther(world, i)`, which `railLinks` never reports. A ramp may be placed on the end of lines that are there (low end on ground track, an elevated ramp's high end on elevated track). `BUILDING_SUBWAY_STATION` 18 is a one-tile entrance (the anchor and the whole surface shape) over THREE tiles of subway platform (the entrance over the middle one), `subwayPlatform(kind, rot)`: west–east at rotation 0, north–south at 1, no other turn (placement rule `twoWay`). The platform is plain subway track, laid under whatever stands there. Cleared, a ramp's two ends and a station's platform stay as track; while the building stands its subway track cannot be dug out (`World.subwayHeldBy`). Tools `rampElevated`, `rampSubway`, `subwayStation`; `placementFor` turns them to join track (`meetsTrack`). Costs in `BALANCE.buildings[16–18]` (placeholders). **Not yet:** nothing rides them (TransitSystem is ground only until PR C).

**Traffic on all rail levels (phase 2, C)** (tests in `railLevelsTraffic.test.ts`): the traffic network has FOUR nodes per tile (`NODES_PER_TILE`): the road (the tile index), then the ground, elevated and subway track at `railSlot(level) × tiles + i` (`railNode(d, i, level)`); the tile of any node is `node % tiles`. Every field and volume array is four nodes per tile, and per-track arrays (`data.rail.capacity`, the junction counts) are indexed `node − tiles`, so plain tile index for ground track as before. `railVolume`, `railLoad`, `railCapacity` take a level (ground by default). Track joins its own level; a ramp joins its low end's ground node to its other end's node (it takes the neighbour slot between the two tiles) and passing its high end costs `BALANCE.rail.rampTime`. A subway station is a portal like a train station, to the subway node under its entrance. Speed, capacity, jam and junction rules are the same on every level; only ground track has level crossings. `stationPeak(world, tx, ty)` gives a station's busiest platform tile, its level and riders, for either kind of station. The traffic overlay draws every level (elevated with a white edge, subway dashed) and the inspector shows riders for elevated track overhead and a subway underneath, whatever stands on the tile. With no rail the pass costs the same as before (10.8 ms on the test city).

**Track nuisance and station growth (phase 2, D)** (tests in `railNuisanceGrowth.test.ts`): laying ground or elevated track near homes costs political capital, through the same nearby-homes cost as an industrial zone: the quote action `{ type: 'track', tx, ty, level }` charges `BALANCE.politicalCapital.nuisance.trackPerResident[level]` (ground 0.01, elevated 0.015, subway 0; owner-approved) per resident in the shared bands. `BuildTrackCommand` charges and refunds it and is refused with `'politicalCapital'` when the city is short; the hover and the Auto plan (`AutoRailPlan.pc`) tint the homes and show the price only when short, like zoning. Stations and ramps cost none. **Growth:** homes and shops (not industry) within `BALANCE.rail.stationGrowth.radius` (4, manhattan, from any tile of the building) of a station that has a road and riders grow `mult` (1.4) times as fast: `stationGrowthMask(world)` in `sim/rail.ts`, read by `ZoneGrowthSystem`; the inspector says so on such a lot. With no served station the mask is null and growth is exactly as before (golden untouched).

**Rail tools, auto mode** (`input/autoRail.ts`, tests in `autoRail.test.ts`): the three track tools share the road tools' Manual / Auto setting. In Auto, a click sets a start and a second click lays the line as one undo step (`InputController._autoRoadClick`; the start is `autoRoadStart`, as for roads). Unlike the road's simple L, `autoRailPath(world, start, end, level)` SEARCHES (A* over tile + direction entered) for the cheapest way on the tool's level under the hand tool's placement rules, where cost is the money for new track plus penalties in tiles of track: at least 12 for making a 3-way junction or for each existing track tile a new tile would lie beside and join, at least 40 for a 4-way, 4 for a new level crossing (ground), 0.5 a bend; a step along existing track costs no money but counts as one tile. So it goes round a line, a street end or a building when the detour is short, and uses a line's free end without a junction. Ending BESIDE the free end of a line, a platform or a ramp costs nothing either (it makes no junction; `beside` charges a join only for the junction it makes), so a line runs straight into a station two tiles away. It returns `AutoRailStep[]`: each tile with its `level`, and for a ramp tile `ramp: 'low' | 'high'` (and `rot` on the low tile). **Bridging (ground only):** a second search layer lets a ground line go up a ramp (low end, high end), over anything elevated track may pass (a line, a highway, a street, water), and down a ramp; that costs two ramps and the elevated tiles in real money, and the 3-way penalty is raised to 0.6 × that so a bridge always beats joining a line and leaving it. With no room for ramps it falls back to join, follow one tile, leave (two 3-ways). Ramp ends need open land (no road, track, zone or building); a bridge keeps one tile clear of existing elevated track. Null = no way (the preview says so and the click does nothing). `planAutoRail` prices it (track by level, ramps, and the PC of the new track); `autoRailPathCached` is for the per-frame preview in `main.ts`. Among tied routes the search follows the one furthest along (without that it looked at every staircase), and it gives up after 250,000 states. Measured: 2 ms corner to corner on an empty 256 map, 10 ms across the 128 test city, about 100 ms when the end cannot be reached on a 256 map. It does not notice the new line running beside ITSELF (a hairpin one tile wide would join up).

**Running costs that grow with the city** (`sim/runningCost.ts`, tests in `runningCost.test.ts`; owner, 2026-11-20, pacing): `EconomySystem` charges `headcountCost(world).total` a tick on top of road and building upkeep. That is, a day, `BALANCE.runningCost.perResident[kind]` for each resident a police station, fire station, school or hospital covers (read from the coverage layers), plus `perUnit[utility]` for each unit of power, water and sewage supplied (demand up to supply), with large plants at `largePlantMult`. All of it is scaled by (population − `freeResidents`) ÷ population, so a town under 1,000 pays nothing extra. Police and fire have a capacity too now (`BALANCE.service.capacity` 4: 3,000, 5: 4,000), seated like schools and hospitals (`sim/serviceCapacity.ts`). The debug economy panel shows the per-resident share.

**Merged 2×2 lots** (`sim/lots.ts`, BIG_LOTS_DESIGN.md, tests in `lots.test.ts`): four top-level lots of one zone as one building. They stay zone tiles: each is at `devLevel` 4 with its quarter (1–4, NW the anchor) in `layers.lot`; `world.lotAnchor(i)` / `lotTilesAt(i)` find the whole. `BALANCE.growth.maxLevel` stays 3, so **a level can be 4: never index by level without allowing for it**, and where a system multiplies by the level use `levelWeight(dev)` (4.5 for a merged tile), with `popPerLevel[4]` for residents. It is one building: `World.razeLot(i)` brings all four tiles down, and `setZone`, `setRoad`, `placeBuilding` and `clearTile` call it; a command that changes a tile snapshots the whole lot (`tilesClearedWith`, `withLots`). It declines as one: `AbandonmentSystem` judges it at its anchor on the worst tile and abandons all four together, `FireSystem` rolls once for it and burns it whole, `zonesCutOffByHighway` cuts off all of it or none. When they merge: `LotMergeSystem` (last but one in `createSystems`), once a game day, from `BALANCE.lots` (streak in `world.lotStreak`, saved as an optional layer); a lot counts when it is happy and in a prime spot (`primeSpot`: top tenth for jobs nearby, or by a park or water and at least the median; industry anywhere), and merged lots keep `spacing` tiles apart; it ships on: `chancePerDay` 0.003 for homes and shops and `industryChancePerDay` 0.0006 for industry (a merge roll draws random numbers, so the shared stream shifts once blocks are ready); with both at 0 the system touches nothing and draws no random numbers. A merged tile with no road of its own uses its building's: ask `doorTile(world, i)` before looking at a lot's neighbouring roads (traffic, accessibility and the road warning do). `lotCounts(world)` and the `lotMerged` event are for the lab. Debug: the Merge 2×2 and Merging: off/on buttons. Save version 11.

**Leisure buildings** (`sim/leisure.ts`, LEISURE_DESIGN.md, tests in `leisureBuildings.test.ts`; part 1 of 4): kinds 19–23 (big park 3×3, beach park 3×2 at the water's edge and the only one that turns, plaza 2×2, museum 2×2, stadium 4×4 plus a 2-tile entrance plaza), all ordinary entries in `world.buildings`, every tile 'body'. One table, `BALANCE.leisure.kinds[kind]` (the 1×1 park has a row too): `category` ('parks' repeatable, 'unique' one per city through the `onePerCity` placement rule), `unlockPopulation` (`buildingUnlocked(world, kind)`; `PlaceBuildingCommand` refuses with `failReason` 'locked'; `World.placeBuilding` itself does not check), `pcCost` (a `bigProject` part in `pcQuote`, refunded by undo, not by bulldozing), `landValue` (`addLeisureLandValue`, step 3c of `LandValueSystem`: full bonus on tiles touching the building, falling to nothing past `radius`; the system's reach grows to the largest radius), `countsAsPark` (the prime-spot rule of merged lots). `beachTilesNear` is for drawing. No traffic, visitors or income yet (parts 2–4). All numbers are placeholders for ENGINEER 3. The tools are in a `leisure` toolbar family shown with `?debug=true` only, until GRAPHICS builds the two categories. No save change.

**Leisure traffic** (`sim/leisureTraffic.ts`, tests in `leisureTraffic.test.ts`; part 2 of 4): a sixth traffic market, `leisure` (`world.traffic.leisure`). Origins: homes (`BALANCE.leisure.tripsPerLevel`) and tourists at the gateways (`touristsArriving` = `cityPull`, the sum of `pull` over attractions on a road, capped by `gatewayCapacity`, `BALANCE.leisure.gateways`: the airport). Doors: every leisure kind with a `capacity` (the stadium and the 1×1 park have none yet). **Appeal is a door handicap**: a `DoorProvider` may pass `add(road, cap, handicap)`, and the flood starts that door at `handicap` street tiles instead of 0 (`leisureHandicap` = best appeal in the table − its own). A map with handicaps has `field.handicapped` true: `dist` includes the handicap, doors are no longer first in `order`, and a door on the way to a better one has a parent and is driven past (it still takes overflow in `_spill`). `BALANCE.leisure.reach` is the market's reach, handicap included. Tickets: `leisureTicketIncome` (added in `EconomySystem`). Free attractions send `shopShare` of last pass's arrivals on as shopping trips (whole trips, one pass behind). For the UI: `attractionAt`, `tourismInfo`, `leisureReachAt(world, tile)` (0–1, the "To leisure" bar), `drawsTourists(kind)` and `hasGateway(world)` (the no-gateway warning). With no attraction on a road the market is idle and costs nothing. Kind 24 `BUILDING_MID_PARK` is a 2×2 park (owner 2026-11-20).

**The leisure need** (part 3 of 4; `BALANCE.leisure.need`): a home growing to level 3 (`ZoneGrowthSystem`) or four homes merging into a tower (`LotMergeSystem`) with no attraction in reach has its chance multiplied by `growthMult` (0.5: slowed, not stopped). `leisureGrowthMult(world, i, toLevel, door)` is the rule; `lacksLeisure(world, i)` is for Inspect. It is 1 in the tutorial city and before the first traffic pass. The 1×1 park is a small attraction (capacity 4, low appeal), so **any city with a park on a road now runs the leisure market** and its homes send leisure trips. It changes probabilities only: no extra random numbers are drawn.

**Event days** (`sim/eventDays.ts`, `systems/EventDaySystem.ts`, tests in `eventDays.test.ts`; part 4 of 4; numbers in `BALANCE.leisure.event`): on Saturdays (`sim/calendar.ts`) a stadium with a road fills. A seventh traffic market, `event` (`world.traffic.event`), has doors on event days only (`MarketDef.occasional`: when its doors appear or go, the pass runs `ITERATIONS_AFTER_EDIT` rounds, like a road edit); homes send `fansPerLevel`, tourist fans arrive at the gateways. `eventTicketIncome` pays for the fans in the seats (fans beyond `reach` of travel time, which jams lengthen, do not come). On the last tick of the event day `judgeEventDay` counts homes **stuck** (a road beside them at `jam.load` × capacity with the crowd at least `jam.eventShare` × capacity of it), charges PC (`eventJam`), and moves `world.eventStrain` (+1 stuck, −1 not); at `dropAfter` a home loses a level (`tileDeclined` with reason 'event'; merged lots never drop). The result is `world.lastEvent` and the `eventDayEnded` event. `eventStatus(world)` is for the pin and the animation (daysToEvent, eventToday, phase, fans, seats, last). No random numbers. Save: `layers.eventStrain` and `lastEvent`, both optional, no version bump.

**Rail traffic** (`TransitSystem`, tests in `railTraffic.test.ts`): every tile of track is a second NODE of the traffic network, numbered tile + n (`world.traffic.tiles`), so all field and volume arrays are two nodes per tile and a `parent` or `order` entry `>= tiles` is track. A station is a portal: each of its access roads is tied to one platform tile at `BALANCE.rail.boardTime` a crossing, both ways. A market with `rides: true` (shopping, jobs, visitors) may pass through portals in its flood, so a trip rides exactly when that is faster and the sweep loads the track instead of the roads; goods and exports never ride. Accessibility floods ride too, so a suburb joined to town only by rail has access. No walking: both ends need a road, and a station with no access road is no portal. Track cost is `1 / rail.speedMult` a tile, slower past free flow of `rail.capacity`; past `rail.jam.from` of capacity (shipped 1.0) a line JAMS: every tile takes `jam.delay × (load − jam.from) ^ jam.power` street tiles longer (load counts up to 3), in street tiles and not as a multiple of the track's own small time, so a jammed line can lose to a slower second line or to the road. The jam is applied at once, not eased like the other costs: eased, a cost that steep made riders swing between two lines in slow waves that never settled; applied at once they swap every round or two and the volume averaging turns that into a steady split. A station's `boardings` come from the last round, so with riders split between two lines the per-station figure can flicker though the total does not; a 3-way or 4-way junction adds `junction3/4.delay` and multiplies capacity by `capacityMult`; at a level crossing the road tile gets `crossing.carDelay` × rail load × road load (each up to 1) and the track `crossing.trainDelay` × road load (owner 2026-11-19, rail.crossing); the traffic overlay and the drawn cars show the crossing's road with its capacity cut by `crossing.overlayCut` × rail load (`shownRoadLoad` in TrafficData.ts; looks only, `layers.congestion` is untouched). A pass does not count as settled while a track or crossing cost is still easing to its target. Stations have no limit. Riders boarding pay `rail.fare` (`railFareIncome`, added by EconomySystem). Published: `world.traffic.rail` (`capacity` per tile, `stations` with `roads` and `boardings`, total `boardings`), `railVolume(d, i)`, `railLoad(d, i)`. With no station that has a road nothing rides and the road results are unchanged (the golden test hashes the road half of the volumes). Measured on the test city (128×128, 1,294 road tiles): a pass with no rail costs the same as before (about 10 ms for a full recompute); with 482 track tiles and 12 stations, 13 ms. Near-equal rail and road times split the trips steadily, with no swinging between passes. The tile inspector shows a station's riders boarding and fares (or its no-road warning) and a track tile's riders against capacity, with a note on a junction or level crossing (`stationRows`, `railRows` in `ui/TileInfoPanel.ts`). Riders get on and off at ONE platform tile of a station (the middle one), so its other platform tiles can carry nobody: for "the riders at this station" use `stationBusiestTile(world, tx, ty)` in `sim/rail.ts` (the inspector and the overlay do), never one platform tile. **The traffic overlay** (`TrafficOverlay._drawRail`) draws track as a line coloured by `railLoad` on the roads' scale, a junction as a disc (white ring and "!" when over capacity), and a label on each station: riders using it (on, off and through) per tick, or "No road".

**Chunked dirty tracking:** 16×16 tile chunks. Mutations call `grid.markDirty(tx, ty)`. A dirty mark means "check this chunk", not "redraw it": `ChunkCache` compares a per-chunk content signature and redraws the cached chunk canvas only if it changed. The signature (`chunkSignature`) sits next to the drawing (`paintChunk`) in `src/render/chunkPainter.ts`. **If `paintChunk` starts reading a new layer, mix that layer into `chunkSignature` too**, or the chunk will not update when it changes; `chunkPainter.test.ts` fails if one is missing. Reduce the value to what is actually drawn (a threshold, a bucket), so sim noise does not cause redraws. Per-frame art (clay sprites, overlays, fire, cars, badges) is not cached and is unaffected.

**The renderer's call:** `renderer.render(world, camera, { hoverTile, tool, overlay, coveragePreview, now })`; every option is optional. Anything cached at a tile size (a baked sprite, a tree clump, a car) uses a `RebakeBudget` so it is drawn stretched while the zoom moves and re-made a few per frame once it stops; do the same for any new cache, or zooming will stutter again. After a change to drawing code that is not meant to change the look, `npm run bench` before and after: the `picture` values must be identical.

**TypeScript constraints:** `erasableSyntaxOnly: true` — no constructor parameter properties. Use explicit field declarations + assignment in body. `verbatimModuleSyntax` — use `import type` for type-only imports.

### The "nothing changed" test

`goldenCity.test.ts` runs the whole simulation (every system, via `createSystems()`) on the test city for 400 ticks and compares a fingerprint — a hash of every tile layer and of the traffic volumes, plus stats and budget — with the stored one in `__snapshots__/goldenCity.test.ts.snap`.

## Save compatibility (owner, 2026-11-19)
The game is live, and players keep cities in their browsers. A change must never silently break a save.
- **Additions** (a new layer, list or field): old saves load with a sensible default. No version bump.
- **Changes to the shape or meaning of saved data:** bump `SAVE_VERSION` (`src/persistence/SaveFormat.ts`) and add an upgrade step vN→vN+1, with a test.
- **Convert in place where possible.** If something can't carry over, remove it, refund its full price (money and PC), and show the player a notice on load saying what changed.
- **Fixtures:** keep one save from every version in `src/__tests__/fixtures`; a test loads them all on every PR.
- **Backup:** before an upgraded save overwrites the player's autosave, keep the old one so a bad upgrade can be recovered.
- **Newer saves** than the running build get a clear message, never a half-loaded city.
- **PRs say so:** "Save format: vN → vN+1, upgrade tested". Upgrade or rebuild the showcase save (`public/showcase/`) with it.
- **Where each of these lives** (ENGINE, 2026-11-19):
  - Fixtures: `src/__tests__/fixtures/saves/vN.citysave.json`, one per version, loaded by `saveFixtures.test.ts`, which FAILS until a file exists for the current `SAVE_VERSION`. Never edit or regenerate one; the README there says how to add the next. v1 to v8 are reconstructed (no saves from those builds were kept).
  - Backup: `SaveManager.loadGame(slot, backupSlot)`. `main.ts` loads the autosave with `AUTOSAVE_BACKUP_SLOT` (−1): when the stored autosave is not of the current version, or cannot be read, the record is copied there as it is (`IStore.copy`, version kept) before any autosave can overwrite it. The Load panel shows it as "Autosave from before the last update". One backup: a later upgrade replaces it.
  - Newer saves: `migrate` and `decodeSaveFile` throw `NewerSaveError`. At launch the player gets a toast (and the save is in the backup slot); a slot or a file that will not load gives an alert with the reason.
  - Telling the player what an upgrade changed: an upgrade step puts a count in the snapshot's `upgradeNotes` (never saved); `deserialize` copies it to `world.loadNotes`, and `showLoadNotes` in `main.ts` turns it into one toast. Add a field and a string for the next one.

## Lessons from Previous Sessions

- Don't claim bugs are fixed without running the code. If you can't verify in a browser, say so.
- Lead with "what is the observed state" before theorizing about causes.
- Don't use `else if` chains when checking multiple independent directions (road-access bug precedent).
- Zone colors should be defined as a cohesive palette with contrast checked against terrain colors.
- Pollution diffusion must be **conserving** (Laplacian step subtracts what it spreads) — additive diffusion causes values to grow unboundedly even with decay.
- When a user says zones can develop without a resource, check whether the growth gate uses `dev[i] >= N` as a guard — that means the resource is only required for levels ≥ N, which may not be the intended behaviour.
- **Typed-array accumulation rates must be ≥ 1**, or `Math.floor` truncates them to 0 every tick (sickness bug: `sicknessRate: 0.08` → never accumulated). Prefer integer ±1 increments gated by a probability roll (`if (rng() < prob) layer[i]++`) over fractional additive rates. This also makes accumulation feel organic rather than mechanical — each zone's trajectory diverges. Apply this pattern to any new `Uint8Array` accumulator (sickness, education, etc.).
